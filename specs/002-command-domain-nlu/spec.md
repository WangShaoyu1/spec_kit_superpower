# 功能规范: 智能厨电指令域语义理解系统

**功能分支**: `002-command-domain-nlu`
**创建时间**: 2026-03-03
**状态**: 草稿
**输入**: 用户描述: "构建面向智能厨电设备的指令域语义理解模块，接收上游 ASR 模块输出的文本，准确识别用户的设备控制意图和菜谱操作意图，提取关键槽位信息，并输出结构化指令。菜谱操作需与设备端 UI 界面联动。"

## 用户场景与测试 *(必填)*

### 用户故事 1 - 设备控制指令识别 (优先级: P1)

用户在烹饪过程中通过语音对厨电设备下达控制指令（如"开始烹饪"、"把火调小一点"、"暂停"、"定时 15 分钟"），系统接收上游 ASR 转写的文本后，准确识别出用户的控制意图和相关参数（设备名称、操作类型、温度值、时间值等），输出结构化的设备控制指令供下游执行模块消费。

**优先级原因**: 设备控制是智能厨电产品的核心价值，直接关系到用户安全和基本使用体验，必须最先实现且准确率最高。

**独立测试**: 可以通过输入一批设备控制相关的测试文本，验证意图分类和槽位提取的准确率是否达到 F1 ≥ 0.95，独立交付设备控制语义解析能力。

**验收场景**:

1. **给定** 系统已加载设备控制意图模型, **当** 输入文本"开始烹饪", **那么** 输出意图为 `command.cooking.start`，置信度 ≥ 0.9
2. **给定** 系统已加载设备控制意图模型, **当** 输入文本"把火调到 180 度", **那么** 输出意图为 `command.temperature.set`，槽位包含 `{temperature: 180, unit: "℃"}`
3. **给定** 系统已加载设备控制意图模型, **当** 输入文本"帮我定个 15 分钟的闹钟", **那么** 输出意图为 `command.timer.set`，槽位包含 `{duration: 15, unit: "分钟"}`
4. **给定** 系统已加载设备控制意图模型, **当** 输入文本"关掉烤箱", **那么** 输出意图为 `command.device.stop`，槽位包含 `{device: "烤箱"}`
5. **给定** 系统已加载设备控制意图模型, **当** 输入一段含混不清的文本（如"那个东西弄一下"），置信度 < 阈值, **那么** 系统触发澄清对话，返回澄清提示而非静默回退

---

### 用户故事 2 - 菜谱操作指令识别与 UI 映射 (优先级: P1)

用户通过语音在厨电设备上操作菜谱（如"搜一下红烧肉怎么做"、"下一步"、"收藏这个菜谱"、"筛选 30 分钟以内能做好的菜"），系统识别菜谱操作意图和关键参数后，输出的结构化指令能够直接映射为设备端菜谱 UI 界面的操作（页面跳转、列表筛选、步骤切换等），使语音操作与手动触屏操作体验一致。

**优先级原因**: 菜谱操作与设备控制同属指令域核心能力，且需要与设备 UI 深度联动，是产品差异化的关键功能。

**独立测试**: 可以通过输入菜谱相关测试文本，验证意图分类和槽位提取的准确率，并验证输出的结构化指令格式是否符合 UI 操作协议规范，独立交付菜谱语音操控能力。

**验收场景**:

1. **给定** 系统已加载菜谱操作意图模型, **当** 输入文本"搜一下红烧肉怎么做", **那么** 输出意图为 `command.recipe.search`，槽位包含 `{dish_name: "红烧肉"}`，映射 UI 操作为 `{action: "navigate", target: "search_results", params: {query: "红烧肉"}}`
2. **给定** 用户正在浏览菜谱步骤页面, **当** 输入文本"下一步", **那么** 输出意图为 `command.recipe.step_next`，映射 UI 操作为 `{action: "step_navigate", direction: "next"}`
3. **给定** 用户正在浏览菜谱详情, **当** 输入文本"收藏这个菜谱", **那么** 输出意图为 `command.recipe.favorite`，映射 UI 操作为 `{action: "favorite", target: "current_recipe"}`
4. **给定** 用户在菜谱列表页面, **当** 输入文本"只看素菜，半小时以内能做好的", **那么** 输出意图为 `command.recipe.filter`，槽位包含 `{category: "素菜", max_duration: 30, duration_unit: "分钟"}`，映射 UI 操作为 `{action: "filter", params: {category: "素菜", max_duration_minutes: 30}}`
5. **给定** 用户在菜谱列表页面, **当** 输入文本"推荐几个简单的早餐", **那么** 输出意图为 `command.recipe.recommend`，槽位包含 `{difficulty: "简单", meal_type: "早餐"}`

### 用户故事 3 - 多轮对话上下文理解 (优先级: P2)

用户在连续交互中使用指代（"它"、"这个"）、省略（上文提到烤箱后直接说"关掉"）或上下文切换（从菜谱浏览切到设备控制），系统能够维护对话状态，正确消解指代和恢复省略信息，保证多轮场景下指令理解的连贯性。

**优先级原因**: 真实使用场景中用户极少用完整句子下达指令，多轮上下文理解是从"能用"到"好用"的关键跨越。

**独立测试**: 可以通过构造多轮对话测试集，验证系统在上下文场景下的意图分类和槽位补全准确率，独立交付多轮对话理解能力。

**验收场景**:

1. **给定** 上一轮用户说"把烤箱温度调到 200 度"且系统已识别设备为烤箱, **当** 用户接着说"调高一点", **那么** 系统能消解"调高"的对象为烤箱温度，输出 `command.temperature.adjust`，槽位包含 `{device: "烤箱", direction: "up"}`
2. **给定** 上一轮用户搜索了"红烧肉"菜谱, **当** 用户说"收藏它", **那么** 系统能消解"它"为当前菜谱，输出 `command.recipe.favorite`
3. **给定** 用户正在浏览菜谱步骤, **当** 用户突然说"暂停烹饪", **那么** 系统能正确识别为跨域切换（从菜谱域切到设备控制），输出 `command.cooking.pause`
4. **给定** 用户说"搜个番茄炒蛋"，系统返回结果后, **当** 用户说"第二个", **那么** 系统能理解为选择搜索结果列表中的第二项

---

### 用户故事 4 - 低置信度澄清对话 (优先级: P2)

当系统对用户输入的意图分类置信度低于阈值时，系统不会静默回退或随意执行，而是触发澄清对话，通过提供选项或反问引导用户明确意图。

**优先级原因**: 厨电设备误操作可能导致安全风险，澄清机制是安全性的重要保障。

**独立测试**: 可以通过输入一批模糊/歧义文本，验证系统是否正确触发澄清而非错误执行，独立交付安全兜底能力。

**验收场景**:

1. **给定** 系统收到文本"弄一下", **当** 意图分类置信度低于阈值, **那么** 系统返回澄清提示"您是想开始烹饪，还是调节温度？"
2. **给定** 系统收到文本"快一点", **当** 存在多个可能意图（加速烹饪、跳过菜谱步骤）, **那么** 系统返回选项列表供用户选择
3. **给定** 系统连续三次未能理解用户意图, **当** 第三次仍无法识别, **那么** 系统按渐进式策略提供兜底响应

---

### 用户故事 5 - 多样化表达识别 (优先级: P3)

用户对同一意图可能有多种不同的自然语言表达方式（方言化口语、简写、同义替换等），系统能够将这些多样化表达归一化到正确的意图和槽位。

**优先级原因**: 覆盖更多表达方式可以提升用户满意度，但在核心指令准确率已达标后再优化。

**独立测试**: 可以通过构造包含多种表达变体的测试集，评估意图分类的召回率和鲁棒性。

**验收场景**:

1. **给定** 系统已加载意图模型, **当** 输入"把火关了"、"关火"、"熄火"、"火关掉", **那么** 均识别为 `command.cooking.stop`
2. **给定** 系统已加载意图模型, **当** 输入"看看有啥好吃的"、"推荐点菜"、"今晚吃啥", **那么** 均识别为 `command.recipe.recommend`
3. **给定** 系统已加载意图模型, **当** 输入包含口语化数字"定个十来分钟的计时器", **那么** 能正确提取时间槽位 `{duration: 10, unit: "分钟", approximate: true}`

---

### 边界情况

- 当输入文本为空或仅含标点符号时，系统返回错误提示而非崩溃
- 当输入文本超长（> 500 字符）时，系统截断处理并记录告警日志
- 当输入文本包含混合意图（如"关掉烤箱然后搜一下蛋糕的做法"）时，系统能拆分为多个独立指令依次处理
- 当设备能力描述文件中不包含用户提到的设备类型时，系统返回"当前设备不支持该操作"的友好提示
- 当用户在同一轮输入中同时包含指令和闲聊内容（如"帮我关火，对了今天天气怎么样"）时，系统优先处理指令部分
- 当 NLU 推理延迟超过 200ms 阈值时，系统记录性能告警但仍返回结果

## 需求 *(必填)*

### 功能需求

- **FR-001**: 系统必须接收文本输入并通过统一 NLU Pipeline 输出结构化的意图分类结果，包含意图标签和置信度分数
- **FR-002**: 系统必须支持层级化意图体系，顶层域为 `command`，子意图至少覆盖：`cooking.start`、`cooking.pause`、`cooking.stop`、`temperature.set`、`temperature.adjust`、`timer.set`、`timer.cancel`、`device.query_status`、`recipe.search`、`recipe.filter`、`recipe.recommend`、`recipe.favorite`、`recipe.step_next`、`recipe.step_prev`、`recipe.step_goto`
- **FR-003**: 系统必须从用户输入中提取关键槽位，至少包括：设备名称、操作类型、温度值及单位、时间值及单位、菜名、食材、口味偏好、烹饪难度、菜谱步骤编号
- **FR-004**: 系统必须将菜谱操作意图的语义理解结果映射为设备端 UI 可消费的结构化操作指令，包含 `action`（操作类型）、`target`（目标页面/组件）、`params`（参数），格式遵循与设备端 UI 约定的协议
- **FR-005**: 系统必须维护对话上下文状态，支持在多轮对话中进行指代消解（如"它"、"这个"指代上轮提到的实体）和省略恢复（如上轮提到烤箱后直接说"关掉"）
- **FR-006**: 系统必须在意图分类置信度低于可配置阈值时触发澄清对话，生成澄清提示或选项列表
- **FR-007**: 系统必须支持通过意图注册机制扩展新意图，无需修改核心 Pipeline 代码
- **FR-008**: 系统必须支持混合意图输入的拆分处理，将包含多个意图的单次输入拆分为有序的独立指令
- **FR-009**: 系统必须通过设备能力描述文件（Device Capability Profile）获取当前设备支持的操作范围，对超出能力范围的指令返回友好提示
- **FR-010**: 系统所有用户可见的响应文本必须支持国际化，默认中文简体

### 关键实体

- **Intent（意图）**: 表示用户输入的语义目的，包含域标签（command）、子意图标签、置信度分数；采用层级化命名空间（如 `command.cooking.start`）
- **Slot（槽位）**: 从用户输入中提取的关键参数实体，包含槽位名称、值、数据类型、是否必填；与意图关联，一个意图可包含多个槽位
- **DialogContext（对话上下文）**: 维护多轮对话状态的实体，包含当前活跃域、最近 N 轮的意图和槽位历史、活跃实体栈（用于指代消解）
- **UICommand（UI 操作指令）**: 菜谱操作意图映射后的结构化输出，包含操作类型（navigate/filter/step_navigate/favorite）、目标、参数；由设备端 UI 直接消费
- **DeviceProfile（设备能力描述）**: 描述特定厨电设备支持的操作集合，包含设备类型、支持的意图列表、参数范围约束（如温度范围 50-300℃）

## 成功标准 *(必填)*

### 可衡量的结果

- **SC-001**: 用户下达设备控制指令后，系统在 200ms 内返回正确的结构化指令，指令类意图 F1-Score ≥ 0.95
- **SC-002**: 用户通过语音操作菜谱时，体验与手动触屏操作一致——语音说"下一步"和手指点击"下一步"按钮触发相同的 UI 行为
- **SC-003**: 在包含指代和省略的多轮对话场景中，系统上下文理解准确率 ≥ 85%
- **SC-004**: 面对模糊/歧义输入时，系统 100% 触发澄清对话而非错误执行设备操作
- **SC-005**: 同一意图的 10 种以上不同自然语言表达方式，系统能正确归一化识别，召回率 ≥ 90%
- **SC-006**: 系统在单次请求内完成意图分类 + 槽位提取 + UI 指令映射的全链路处理，端到端延迟 < 200ms（P95）
- **SC-007**: 新增一个子意图从定义到上线可在 1 个工作日内完成，无需修改核心 Pipeline 代码
