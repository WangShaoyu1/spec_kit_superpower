# 整体UI配色存在很大的问题，布局存在很多非必要的文字

## 现象
1、整个系统的配色是黑色，非常难看，见截图 [](./images/D002-1.png)
2、左上角：“Spec Harness Console SmartChef  正式前端壳。试点入口已经退出，后续模块按 harness 顺序逐个接入。”
3、右上角：“Local PG via temp_data/manage_services.py”
4、纵览驾驶舱，这个页签的必要性，如有必要是不是可以转为一个 大drawer ，放在右上方某个位置点击触发，是不是更好一些


## 期望
1、期望按照 skill，front-design 和  vercel-react-best-practices，这两个skill来重新修缮一下 目前的UI，还有UI布局
2、通篇自纠自查，和项目无关的展示内容

## 复现步骤
1. 打开当前后台首页壳层
2. 观察整体深色主题、左上角说明文案、右上角环境按钮和“总览驾驶舱”入口
3. 对照当前手动验收目标，识别与业务无关或表达过重的信息

## 根因
当前前端壳层仍保留了较强的“研发过程展示”痕迹，而不是完全站在最终验收用户视角组织信息。

具体表现：

- 主题使用了偏重的深色工业风，与当前后台管理场景不匹配
- 左上角保留了 `Spec Harness Console`、`正式前端壳`、`harness 顺序接入` 等过程性文案
- 右上角保留了 `Local PG via temp_data/manage_services.py` 这类内部环境信息
- 首页把“总览驾驶舱”作为一级导航，但其内容更多是研发过程说明，不是业务核心入口

这说明问题并不只是“样式 bug”，而是需要先做一次 UI 方向与信息架构收口。

## 修复方案
采用“强收口”方案落地：

1. 取消一级“总览驾驶舱”菜单，避免它成为与业务模块并列的主导航
2. 左侧品牌区只保留 `SmartChef / 管理后台`，去掉研发过程说明
3. 顶部区域改为“平台概览 + 退出登录”双动作
4. 将总览内容改为右侧抽屉，按需展开
5. 主题改为更适合后台验收场景的浅色暖中性色，不再使用重黑色工业风
6. 登录页文案同步收口为业务导向表达

## 修复说明
已完成代码修复。

- `AppShell.jsx` 去掉了“总览驾驶舱”一级导航
- 左侧品牌区删除 `Spec Harness Console`、`正式前端壳`、`harness 顺序接入` 等过程性文案
- 顶部环境按钮 `Local PG via temp_data/manage_services.py` 已移除，改为“平台概览”按钮
- 总览能力改造成右侧抽屉，保留概览信息但不干扰主业务导航
- 全局主题与登录页同步改为浅色、业务导向的后台风格
- `AppShell.test.jsx` 已补回归，锁定新导航结构与概览抽屉行为

验证：

- `npm run test -- src/app/AppShell.test.jsx src/app/App.auth.test.jsx src/modules/user-mgmt/UserMgmtPage.test.jsx`
- `npm run build`

## 设计回溯
本缺陷暴露的是后台壳层入口语义与真实验收使用场景不够一致。

本次修复没有改业务模块契约，但调整了壳层导航策略：

- 平台概览从一级菜单改为顶部抽屉入口
- 壳层表述从“研发过程展示”切回“业务后台入口”

后续若 PD / README 中仍将“总览驾驶舱”定义为一级页签，需要同步修正文档口径，避免再次出现设计与实现漂移。
