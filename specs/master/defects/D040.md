# LLM 训练数据合成接口因提示词模板占位符未注入返回 500

## 现象
调用 `POST /api/v1/datasets/{dataset_id}/generate-training` 进行 LLM 合成时，若请求体中的 `prompt_template` 使用 PD/产品侧常见占位符（例如 `{intent_list}`），接口返回 **HTTP 500 Internal Server Error**（服务端未捕获异常），而非结构化业务错误。

**示例请求**（节选）：
```http
POST /api/v1/datasets/d0d52944-1405-427a-8ff1-22b17fe430f7/generate-training
Content-Type: application/json

{"model_name":"gpt-4o","samples_per_intent":120,"prompt_template":"基于下列意图集合，为用户语料生成多样化口语化表述，保持领域一致：\n{intent_list}"}
```

## 期望
- 提示词模板中声明的占位符均能由服务端注入；若存在**未支持**的占位符，应返回明确业务错误码与文案（如 `E50603`），而非 500。
- 成功时正常返回 `generated_count` / `intent_count` 等字段。

## 复现步骤
1. 在训练数据集中至少配置一个意图。
2. 使用含 `{intent_list}` 的 `prompt_template` 调用 `generate-training`（见上）。
3. 观察响应为 500（修复前）。

## 根因
`data_generation_service.generate_training_data` 使用 `prompt_template.format(count=..., intent_name=..., description=..., examples=...)` 渲染提示词，**未提供** `{intent_list}`（及与 PD 文案可能相关的其它键）。Python `str.format` 对模板中多余占位符会抛出 **`KeyError: 'intent_list'`**，未被转换为 `BusinessException`，故表现为 **500**。

## 修复方案
1. 抽取 `_format_generation_prompt`，统一注入：`count`、`intent_name`、`description`、`examples`、**`intent_list`**（当前数据集全部意图列表文本）、**`intent_key`**；`KeyError` 转为 `BusinessException E50603` 并提示支持的占位符。
2. 评测集 `generate_evaluation_data` 中提示词渲染与训练侧对齐。
3. `datasets.py` 中生成类接口去掉路由内重复 `commit`（依赖 `get_db` 统一提交），避免重复提交风险。
4. 补充单元测试 `tests/unit/test_data_generation_prompt.py`（占位符回归）。

## 修复说明
见 `fix_ref`；若本地未配置 `ZENMUX_API_KEY` / `ZENMUX_BASE_URL`，应得到 **`E50601` 类业务错误**而非 500。

## 设计回溯
建议在 `dd-intent-library` 或数据合成相关章节**显式列出**提示词模板支持的占位符名称，避免前后端与 PD 文案漂移。
