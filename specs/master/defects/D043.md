# 指令库管理，对话过程中无内容反馈回来

## 现象
单条测试会话中发送用户话后，**聊天区不显示助手回复**（或列表为空），而 Network 中 `POST .../test-sessions/{id}/messages` 实际返回 **200** 且 `data` 为两条消息（user + assistant）。

## 期望
- 发送后用户气泡与助手气泡**均能展示**，文案与接口 `content` 字段一致。
- 切换会话时**能拉取历史消息**。

## 复现步骤
1. 指令库 → 模型单条测试 → 选模型 → 新建会话 → 输入一句话发送。
2. 观察聊天区：助手侧无内容或整页为空；接口响应实际含 assistant 的 `content`。

## 根因
1. **`send_message` 返回体**：后端 `success_response` 的 `data` 为 **`[userMsg, assistantMsg]` 数组**，前端误把 `res.data` 当作**单条对象**展开并 `setMessages`，导致气泡结构错误、**无有效 `content` 展示**。
2. **`GET .../messages`**：分页结构为 **`{ items, total, page, ... }`**，前端用 `res.data` 直接当数组；且请求参数误用 **`limit`**（接口为 **`page` / `page_size`**），列表长期为空或条数不对。
3. **批量测试 `parseBotNlu`**：NLU 结果在 **`result.intent` / `result.confidence`**，原逻辑未读 `result`，且未处理 **数组** 返回。

## 修复方案
- 发送成功：去掉乐观 `temp-` 用户消息后，将接口返回的 **消息数组** 整段并入 `messages`。
- `fetchMessages`：使用 **`page_size: 200`**，并从 **`data.items`** 取列表。
-  **`parseBotNlu`**：优先读 **`result`**，并支持入参为 **数组**（取 `assistant` 项）。

## 修复说明
见 `fix_ref`。后端契约未改；问题为前端对分页与 `send_message` 返回形态的解析错误。

## 设计回溯
- 与 `paginated_response` / `success_response(data)` 一致；DD 若只写「返回消息列表」可注明 **发送消息为两条记录的数组**、**列表接口为分页**。
