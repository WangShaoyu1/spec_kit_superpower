# 指令库单条测试，对话接口报错

## 现象
接口：`POST /api/v1/test-sessions/{session_id}/messages`  
入参：`{"text":"你好"}`  
Status Code：**422 Unprocessable Entity**

响应：
```json
{
  "detail": [
    {
      "type": "missing",
      "loc": ["body", "content"],
      "msg": "Field required",
      "input": { "text": "你好" }
    }
  ]
}
```

## 期望
- 请求体与后端 **`SendMessageRequest`** 一致：必填字段 **`content`**（用户输入文本）。
- 前端不得使用与契约不符的字段名（如 `text`）。

## 复现步骤
1. 指令库进入模型单条测试，创建会话后发送一句用户话（旧版前端发 `text`）。
2. 或使用 Postman：`POST .../messages`，body 为 `{"text":"你好"}` → 应 422；**正确 body**：`{"content":"你好"}`。

## 根因
- 后端自始定义为 **`content`**（`app/schemas/intent_library.py` → `SendMessageRequest`）。
- 前端 `Placeholder.jsx` 调用 `sendTestMessage(..., { text })`，与契约不一致。

## 修复方案
- **仅改前端**：`Placeholder.jsx` 改为 `sendTestMessage(..., { content: ... })`。
- **`intentLibraryApi.js`**：为 `sendTestMessage` 补充注释，明确 body 形状为 `{ content: string }`。
- **不修改**后端 schema，不做 `text` 别名兼容。

## 修复说明
见 `fix_ref`。

## 设计回溯
- 以 DD/后端 **`content`** 为准；问题为前端字段名错误，非设计变更。
