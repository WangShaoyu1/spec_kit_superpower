# 没有退出登录功能，登录授权401也没有跳转到登录页

## 现象
http://localhost:4173/api/v1/intent-libraries
响应：
{
    "code": "AUTH-401",
    "message": "未登录或会话已失效",
    "data": null,
    "request_id": "62464c02-bba0-40dd-9783-6881b56f8bbc",
    "timestamp": "2026-04-01T02:56:46.321963Z"
}


## 期望
1、如果前端接口报错401，需要跳转到登录页
2、有显式的退出登录功能

## 复现步骤
1. 使用已登录态进入任一业务页面，例如 `intent-library` 或 `user-mgmt`
2. 让后端返回 `AUTH-401` / 401
3. 观察前端仍停留在业务页，且没有统一回到登录页
4. 同时页面中缺少显式“退出登录”入口

## 根因
前端只在登录时把会话写入 `localStorage`，但没有统一的“会话失效处理器”。
各业务页面直接调用 API，请求返回 `AUTH-401` 后只会抛出异常，不会清理本地会话、更不会跳回登录页。
另外壳层 `AppShell` 里也没有任何显式退出登录按钮，导致用户无法主动结束当前会话。

## 修复方案
1. 在 `frontend/src/services/api.js` 增加全局鉴权失效回调注册能力
2. 在 `frontend/src/App.jsx` 注册统一的 session 清理逻辑：清空 `smartchef-session`、回到 `/`、恢复登录页
3. 在 `AppShell` 增加显式“退出登录”按钮
4. 在页面加载逻辑中对“已处理的 AUTH-401”静默兜底，避免未处理 Promise 冒泡
5. 补回归测试锁定“退出登录”和“401 跳登录页”行为

## 修复说明
已完成代码修复。

- `App.jsx` 现在会统一注册鉴权失效处理，并提供 `clearSession()`
- `AppShell.jsx` 已新增“退出登录”按钮
- `api.js` 已支持全局 `AUTH-401` 处理与 `isAuthFailureError()` 判定
- `UserMgmtPage.jsx` 已对已处理的鉴权失效做静默兜底
- `App.auth.test.jsx` 已新增两条回归：退出登录、401 回登录页

验证：

- `npm run test -- src/app/App.auth.test.jsx src/modules/user-mgmt/UserMgmtPage.test.jsx src/app/AppShell.test.jsx`
- `npm run build`

## 设计回溯
本缺陷暴露的是实现未完全兑现现有设计约束，而不是 AD/DD 本身缺失。

- `ad-global §5.1` 已定义“登录后菜单解析并缓存当前会话”
- `ad-global §6.2` 已定义 `AUTH-401` 为未登录/Token 失效
- `dd-global §3.2` 已要求前端菜单与会话能力点联动

结论：设计文档本身可继续沿用，本次主要是代码与测试补齐；后续建议把“401 自动回登录页 + 显式退出登录”固化到 smoke / auth 回归用例中。
