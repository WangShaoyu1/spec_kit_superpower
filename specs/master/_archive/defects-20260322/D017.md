# 进入到监控仪表盘页面，点击进去"设备日志"、"告警规则" "首页"，这三个页面，直接跳转到登陆页面

## 现象
在已经登录的情况下，进入到监控仪表盘页面，点击进去"设备日志"、"告警规则" "首页"，这三个页面，直接跳转到登陆页面

## 期望
正确进入对应页面

## 复现步骤
1. 使用 admin 账号登录系统
2. 点击左侧导航"监控仪表盘"进入监控概览页
3. 点击子菜单"设备日志"或"告警规则"
4. 页面直接跳转到登录页

## 根因
**双重 bug 叠加：**

1. **Capability key 不匹配（主因）**：`init_db.py` 种子数据注册的权限 key 为 `monitoring_read` / `monitoring_manage`，但 `monitoring.py` API 端点使用 `@require_capability("monitor_read")` / `@require_capability("alert_manage")`。名称不一致导致 JWT 中的 capability 永远匹配不上，API 调用必定返回 `E10107`（403 无权限）。

2. **前端拦截器混淆 403 和 401**：Axios 拦截器对所有 `E101xx` 错误码（包括 `E10107` 权限不足）统一执行"清除 token + 跳转 /login"。`E10107` 实质是"已认证但无权限"，应跳转 `/403` 而非清除 token。

3. **侧边栏重复 key（次因）**：监控子菜单中"概览"项的 key 与父级 key 均为 `/monitoring`，Ant Design Menu 组件在处理重复 key 时行为不确定。

## 修复方案
1. 将 `monitoring.py` 中所有 `monitor_read` → `monitoring_read`，`alert_manage` → `monitoring_manage`，与种子数据保持一致
2. 前端 `api.js` 拦截器增加 `E10107` 专项判断，跳转 `/403` 而非清除 token；同时对纯 HTTP 403 也做同等处理
3. 侧边栏"概览"子项 key 改为 `/monitoring/overview`，`App.jsx` 增加 redirect 路由

## 修复说明
- `backend/app/api/v1/monitoring.py`: 12 处 `require_capability` 调用的 key 全部修正（5 处 `monitor_read` → `monitoring_read`，7 处 `alert_manage` → `monitoring_manage`）
- `frontend/src/services/api.js`: 在 success/error 两条拦截链中增加 `E10107` 前置判断 → 跳转 `/403`（不清除 token）；error 链增加纯 HTTP 403 → 跳转 `/403`
- `frontend/src/components/Layout/MainLayout.jsx`: "概览"子菜单 key 由 `/monitoring` → `/monitoring/overview`
- `frontend/src/App.jsx`: 新增 `<Route path="monitoring/overview" element={<Navigate to="/monitoring" replace />} />`
