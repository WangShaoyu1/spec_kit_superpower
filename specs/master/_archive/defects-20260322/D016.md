# 指令库中涉及到小模型从0-1的全链路缺失，导致在对话管理中配置了指令库也不会生效

> **归档说明**: 本缺陷提出的所有需求已合并至 `spec.md` v1.2/v1.3（FR-039~FR-054），
> PD 交互设计已基于 `spec.md` 独立生成，目录为 `specs/master/pd-intent-library/`（参见 `pd-index.md`）。
> 后续迭代应直接修改 `spec.md` 和对应 PD 模块，本文件仅作历史记录保留。

## 现象
 1、目前指令库只有列表的增删改查功能，跳转到意图列表页面之后也只能单条意图的增删改查，这些信息不足以训练一个小模型
 2、怎么训练，需要什么数据，怎么生成训练数据，训练参数怎么调整，怎么评估训练的小模型的质量，目前都是空白
 3、怎么驱动训练好的小模型，让其集成到某个对话方案中提供指令匹配服务，目前也是空白

## 期望
1、指令库整个模块形成闭环

## 复现步骤
1. 
2. 

## 根因
1. 当前“指令库”仅具备内容管理能力（库/意图 CRUD），缺少“训练数据 -> 训练任务 -> 模型评估 -> 模型发布 -> 运行时生效”的闭环定义。  
2. 对话方案当前仅能绑定指令库，缺少“库内模型版本状态”约束，导致“绑定了库但运行时无可生效模型”的隐患。  
3. 训练集与评估集的数据边界、导入格式、LLM 合成治理规则未定义，无法形成可复现的数据管道。  
4. 模型状态流转、权限边界、发布确认流程未定义，无法支撑可控上线。  
5. 质量门槛与阈值策略缺少统一口径，难以在测试结果中稳定解释“命中/未命中”行为。  

## 修复方案
### 一、范围与分阶段策略（已进入研发与自测）
1. 已完成 D016 第一/二轮研发收口，覆盖“数据集导入 -> 模型评估 -> 测试态/发布态 -> 方案发布门禁 -> 运行时加载 -> 产物下载校验”的主链路。  
2. 当前仍保持“缺陷待确认”，待你完成业务验收后再切为已关闭。  

### 二、模型与指令库关系（V1 定稿）
1. `CommandLibrary` 与模型版本为 **一对多**。  
2. 单库模型数量上限为 **5**（代码常量配置，不在后台页面配置）。  
3. 超限行为：禁止新建训练任务，并提示“请先归档/删除历史模型”。  
4. `published` 唯一性范围为 **每个库唯一**。  
5. `testable` 唯一性范围为 **每个库唯一**；切换 testable 时自动取消旧 testable。  
6. 允许同一模型同时持有 `testable` 与 `published`。  
7. 模型产物必须平台无关：支持下载并可在 Python 应用与 C++ 设备端运行（例如 ONNX/TensorRT 形态）。  

### 三、模型状态机与操作规则
状态机：`draft -> training -> trained -> evaluating -> testable -> published`

补充规则：
1. 从模型 A 切换到模型 B 为 `testable` 时，A 自动取消 `testable`。  
2. `published` 为手动操作，要求二次确认；发布备注非必填。  
3. 支持模型归档；归档后允许恢复为 `draft`（用于回滚实验）。  

### 四、对话方案生效约束（与 D014 联动）
1. 对话方案不强制绑定指令库。  
2. 若方案绑定了某库，则该库必须存在 `published` 模型，否则不允许发布方案并给出明确提示。  
3. 运行时仅加载库内 `published` 模型进行推理，`testable` 仅用于测试页。  
4. 运行时沿用 D014 规则：`unknown` 或得分低于 `command_threshold` 视为“未命中”，直接进入后续链路（知识/闲聊），不跨库回退。  

### 五、训练集/评估集与 LLM 合成治理
1. 训练集与评估集是不同数据集。  
2. 训练关系：一个训练集对应一个模型（1:1）。  
3. 评估关系：模型可复用不同评估集（非 1:1）。  
4. LLM 合成数据在两个场景都支持：  
   - 训练数据生成  
   - 评估数据生成  
5. LLM 治理最小规范：  
   - 必须覆盖全部 `intent_key`  
   - 每个意图至少 N 条（N 可配置）  
   - 必须包含口语化、多表达变体  
   - 提示词有默认模板，可在页面配置  
   - 页面可配置：提示词、生成用 LLM、每意图最少数量  

### 六、Excel 导入字段口径
1. 训练集最小字段固定为：  
   - `intent_key`  
   - `utterance`  
   - `language`  
   - `slots(json)`  
   - `source(manual/llm)`  
2. 评估集采用全字段导入口径：  
   - `intent_key`  
   - `utterance`  
   - `language`  
   - `source(manual/llm)`  
   - `expected_result`  
   - `actual_result`  
   - `threshold`  
   - `actual_score`  
   - `is_hit`  
3. 评估导入时允许 `actual_result/actual_score/is_hit` 为空，由系统评估后回填。  

### 七、质量门槛与阈值配置
1. 质量指标：`intent_f1`、`slot_f1`。  
2. `slot_f1` 仅在“有槽位样本”上计算。  
3. 门禁策略非硬阻断：阈值可配置，测试结果展示“预期值 vs 实际值”。  
4. 阈值配置层级：  
   - 库级默认阈值（`intent_f1` / `slot_f1`）  
   - 批量测试任务创建时可覆盖一次，并写入该次测试记录快照  

### 八、测试入口与智能分析（实现状态）
1. 单条测试入口固定在：`指令库 -> 模型 -> 测试` 页面（对话框式，支持展开详细结果）。  
2. 批量测试页面保留，用于评估集维度验证。两者均为“测试”，粒度不同。  
3. 智能分析在评估完成后自动触发，输出至少包括：  
   - 总体结论  
   - 混淆意图 TopN（默认 5，代码常量）  
   - 槽位错误类型分布  
   - 低分样本清单  
   - 改进建议  

### 九、权限边界
1. 发布权限按能力控制：`model_publish`。  
2. testable 管理权限：`model_test_manage`。  
3. 使用权限判定，不绑定“管理员角色名”。  

## 修复说明
本次已完成 D016 研发收口与自测，关键落地如下：  
1. **模型生命周期与门禁**：实现库内模型 `testable/published` 唯一约束、发布二次确认与备注、方案发布前“库需存在 published 模型”校验。  
2. **数据集链路**：实现训练/评估数据集创建、行级导入（训练最小字段、评估全字段），并支持行数据读取导出。  
3. **评估与分析**：评估任务支持阈值快照、结果回填 `actual_result/actual_score/is_hit`，自动生成结构化智能分析（总体结论、Top 混淆、槽位错误分布、低分样本、建议）。  
4. **测试能力**：实现单条测试接口与前端对话框结果展示（含详情展开）；评估记录可在前端查看分析详情。
