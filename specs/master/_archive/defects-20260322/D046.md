# LLM 数据合成功能为假实现：前端提交成功但样本永远为 0

## 现象

数据集管理页面点击「LLM 合成」→ 填写表单 → 点击确定，前端弹出 `message.warning('LLM 数据合成尚未接入服务端任务与模型管线…')`，实际未调用任何后端 API。即使后续补接了 API，后端使用 `BackgroundTasks` 异步执行并返回 `202 accepted`，但：
1. `ZENMUX_API_KEY` 默认为空字符串，LLM 调用必然失败
2. `_call_llm()` 用 `except: return []` 吞掉全部异常，静默返回空列表
3. 数据集为空（0 个意图）时，生成逻辑遍历空列表，结果为 0 条
4. 前端收到 202 即认为成功，无法感知后台任务的真实结果

最终表现：样本数始终为 0/500，进度条不动。

## 期望

1. API Key 缺失时前端即刻报错"LLM 未配置"
2. 数据集无意图时前端即刻报错"请先添加意图"
3. LLM 调用失败时前端显示具体错误原因
4. 成功时前端显示实际生成条数

## 复现步骤
1. 进入指令库 → 数据集管理
2. 点击「LLM 合成」→ 选择数据集 → 填写参数 → 确定
3. 观察：提示"已提交"但样本数始终为 0

## 根因

三层掩耳盗铃：
- **前端层**：原始代码直接弹 `message.warning` 假提示，根本没调 API
- **后端 API 层**：改用 `BackgroundTasks` + `202 accepted` 模式后，错误被后台任务吞没，前端无法获知结果
- **后端服务层**：`_call_llm` 的 `except: return []` 吞掉所有异常；`ZENMUX_API_KEY=""` 未做前置校验；空数据集无意图时循环体直接跳过

## 修复方案

1. **后端服务层** (`data_generation_service.py`)：
   - 新增 `_check_llm_config()` — API Key 为空立即抛 `BusinessException`
   - `_call_llm()` 不再吞异常，失败时抛 `BusinessException` 携带原因
   - 空意图前置校验：`intents == []` 时直接报错
   - 单意图失败不阻塞其他意图，但全部失败时抛异常
2. **后端 API 层** (`datasets.py`)：
   - 从 `BackgroundTasks` 异步模式改为同步执行，错误直接透传给前端
   - 删除 `_run_generate_*_background` 和 `create_async_engine` 等冗余代码
3. **前端** (`Placeholder.jsx`)：
   - 调用真实 API（`generateTrainingData` / `generateEvaluationData`）
   - `confirmLoading` 状态展示加载中
   - 成功显示实际数量，部分失败显示 warning，全部失败显示 error

## 修复说明
- 后端改为同步执行模式，所有异常（配置缺失、空数据集、LLM 调用失败）均透传至前端
- 前端展示真实生成结果（条数、部分失败详情）
- 样本进度列在无 `sample_target` 时直接显示数量，不再用硬编码 500 作分母

## 设计回溯
- DD 中未明确要求 LLM API Key 的前置校验机制，应补充：凡依赖外部服务的功能，MUST 在调用前校验配置完整性并返回明确错误
- DD 中未规定 LLM 生成接口应同步还是异步，应补充：对于结果需即时反馈的操作，优先同步执行；仅长时间（>30s）任务才使用异步+轮询模式
