# 数据集列表「样本进度」列分母硬编码 500，空数据集显示 0/500 造成假数据错觉

## 现象

数据集管理页面表格中「样本进度」列显示 `0/500`，进度条为 0%。分母 500 是前端硬编码的 `SAMPLE_TARGET_MAX` 常量，并非数据集实际配置的目标值。当数据集本身没有设定 `sample_target` 时，所有数据集均显示 `X/500`，造成：
1. 用户误以为存在 500 条样本的目标但一直未达成
2. 与 D046（LLM 合成不生成样本）叠加，进一步加深"假数据"的印象

## 期望

- 数据集未设定 `sample_target` 时，直接显示实际样本数（如 `0 条`、`120 条`），不显示进度条
- 仅当数据集明确配置了 `config.sample_target` 时，才显示进度条 `cur/target`

## 复现步骤
1. 创建数据集（不设置 `sample_target`）
2. 查看数据集列表
3. 「样本进度」列显示 `0/500`

## 根因

`Placeholder.jsx` 第 261 行：
```javascript
const target = record.config?.sample_target ?? SAMPLE_TARGET_MAX;
```
当 `record.config.sample_target` 为 `undefined`（绝大多数场景），回退到常量 `SAMPLE_TARGET_MAX = 500`，导致所有数据集一律以 500 为分母。

## 修复方案

- 当 `record.config?.sample_target` 不存在时，列标题改为「样本数」，直接显示 `cur 条`（纯文字）
- 仅当 `sample_target` 有值时才渲染 `<Progress>` 组件

## 修复说明

```jsx
const target = record.config?.sample_target;
if (!target) {
  return <Text style={{ fontFamily: 'var(--font-mono)' }}>{cur} 条</Text>;
}
// 有 target 时才渲染 Progress
```

列标题从「样本进度」改为「样本数」。

## 设计回溯
- PD 交互稿中数据集列表的「样本数」列未明确指定是否需要进度条展示形式；前端实现时自行引入了 `SAMPLE_TARGET_MAX` 概念，但无对应的后端字段和业务逻辑支撑。应在 DD 中明确：进度条仅在存在用户设定的目标值时展示。
