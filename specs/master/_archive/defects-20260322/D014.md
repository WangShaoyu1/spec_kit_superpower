# 指令库管理，没有新增指令库功能，同时在对话方案缺少一个核心的配置项

## 现象
1、指令库页面，没有新增指令库功能，无法验证流程。指令库要区分中文、英文两种语种，因为不同的语种的处理逻辑不一致
![现象截图](images/D001.png)
2、对话方案，整个链路上需要配置指令库。因为有两个指令库：中文指令库、英文指令库，需要一起在对话方案上体现，根据自动检测到的语言来响应对应语种的指令库
## 期望
1、对话方案配置页面，增、改操作，需要添加指令库选项（支持多个指令库并行）。
2、用户语言输入为中文，则链路上响应中文指令；用户语言为英文，则链路上响应英文指令。
3、对话方案中增加“指令阈值”配置：与指令库匹配时，得分 > 阈值才视为命中指令，否则进入知识库/闲聊链路。
4、编辑方案弹窗优化：对简单 `Select` / `Input` 组件，采用两列并排布局（2 个 item 并列）提升可读性和效率。

## 已确认范围与约束（定稿输入）
1. 当前固定中文 / 英文两种语种，未来阶段不考虑拓展多语言。
2. 对话方案不再配置语种字段；每个方案允许配置多个指令库并行（典型为中文库 + 英文库）。
3. 自动检测语种为英文时，若英文指令未命中，不回退中文指令库，而是进入指令后链路（知识库或闲聊）。
4. `library_key` 全局唯一且不可修改；如需变更，需删除后重建指令库。
5. 存量迁移策略：现有意图默认迁入中文指令库，英文指令库后续补齐（可接受）。
6. 对话方案新增“指令阈值”配置项，并纳入发布前校验与运行时逻辑。
7. 方案编辑弹窗按表单复杂度细化布局：简单项双列并排，复杂项（长文本/高级配置）保持整行。

## 复现步骤
1. 进入「指令库管理」页面，确认是否可新增指令库并配置语种（中文/英文）。
2. 进入「对话方案配置」页面，新建/编辑方案，确认是否可多选指令库并配置“指令阈值”。
3. 在手动测试中输入英文文本，构造英文库未命中场景，观察是否进入知识/闲聊链路。

## 根因
1. 指令库仅通过 `Intent.category` 聚合展示，不具备独立实体，无法承载语种与 `library_key` 约束。
2. `DialogProfile` 缺少“并行指令库绑定”和“指令阈值”字段，导致方案层无法精确控制命中策略。
3. NLU pipeline 仅使用全量意图分类，缺失语种-指令库筛选与阈值判定，无法满足“英文未命中不回退中文”。
4. 前端方案编辑弹窗采用单列排布，简单配置项可读性和录入效率不足。

## 修复方案
1. 后端新增 `IntentLibrary` 实体（`library_key` 唯一、语种固定 zh/en），并提供新增/编辑/删除 API。
2. 对话方案新增 `intent_library_keys` 与 `command_threshold` 字段，并在发布接口增加前置校验。
3. pipeline 增加“语种指令库筛选 + 阈值判定 + 命中失败降级到知识/闲聊”逻辑，禁止英文回退中文库。
4. 前端改造：
   - 指令库页面支持新增/编辑/删除、语种展示、分页；
   - 对话方案弹窗新增多选指令库和指令阈值，简单项采用双列布局。
5. 增补迁移脚本与测试用例，覆盖 D014 关键行为。
