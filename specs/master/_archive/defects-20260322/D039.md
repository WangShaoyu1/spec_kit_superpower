# 训练 15 秒超时，前端页面提示超时错误

## 现象
- 接口：`POST /api/v1/models/{model_id}/train`
- 入参示例：`{"base_model":"intent-bert-base-zh","learning_rate":0.00002,"batch_size":32,"epochs":1,"early_stopping":true,"early_stopping_patience":2}`
- 前端约 **15s** 后出现超时（与全局 axios `timeout: 15000` 一致）。

## 期望
- 训练为**后台任务**，接口应**快速返回**「已接受训练」状态（如 `status: training`），不应长时间占用 HTTP 连接。
- 前端在训练**真正完成**后得到成功提示（非仅「已提交」）；失败时提示原因。
- **下载**接口返回真实模型包（zip），浏览器可保存文件。
- 前端不应因默认 15s 限制误报超时（提交接口可单独放宽超时作兜底）。

## 复现步骤
1. 在指令库详情对模型版本点击「开始训练」。
2. 观察浏览器 Network：约 15s 失败或前端超时提示。

## 根因
1. **`model_versions` 模块顶层** `from app.services.training.trainer import execute_training` 会在**导入该路由模块时**加载 `trainer.py` → 进而 `import torch`。在部分环境（尤其 Windows）**首次加载 torch 可达十余秒**；若该成本落在**处理请求的进程/时机**上，会导致「开始训练」HTTP 在返回 `success_response` 之前耗时超过 15s，触发 axios 超时。
2. 即便后台任务设计正确，**全局 axios 15s** 对偶发慢应答仍偏紧。
3. **事务与 BackgroundTasks 顺序**：`get_db` 在依赖 teardown 里 `commit`；`BackgroundTasks` 常在**响应发出后**先执行。后台 `execute_training` 用**新会话**读库时，若请求事务尚未提交，仍读到 **`draft`**，轮询列表也一直像「没开始训练」；并可能与未提交状态竞态。

## 修复方案
1. **后端**：移除对 `execute_training` / `execute_batch_evaluation` 的顶层导入；在 **`BackgroundTasks` 调用的异步包装函数内**再 `import` 并 `await`，使重依赖在**响应发送之后**再加载。
2. **前端提交**：对 `trainModel`、`evaluateModel` 单独设置适度 `timeout`（如 60s），作为网络/代理延迟的兜底（**非**用长超时假装「等训练结束」）。
3. **前端闭环**：`POST /train` 成功后，对 **`GET /models/{model_id}`** 轮询（合并 `progress` 到表格），直到 `trained` / `failed`（或超时），再提示；首帧立即请求，不必空等一个 interval。
4. **路由内提交**：`POST /train`（及 `POST .../evaluate`）在 **`background_tasks.add_task` 之前**执行 **`await db.commit()`**，保证后台任务与后续轮询读到已提交的 `training` 状态。
5. **下载**：`GET .../models/{id}/download` 使用 `FileResponse` 返回 `package_uri` 解析后的 **zip 文件**；前端保持 `responseType: 'blob'`，保存为 `.zip`。
6. **测试**：`tests/integration/test_train_http_status.py` 用真实 HTTP + DB，mock `_run_training_background`，断言 **POST 后立即 GET 单模型为 `training`**。

## 修复说明
见 `fix_ref`。仅延长 axios 超时不能替代「异步训练 + 轮询状态 + 文件下载」闭环。

## 设计回溯
与 DD「训练异步、HTTP 仅触发任务」一致；问题在**实现层导入时机**与**客户端默认超时**，非 AD 矛盾。
