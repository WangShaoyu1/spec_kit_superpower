## 建议整改顺序
1. 当前阻塞项已全部收敛，可进入正式验收结论。
2. 后续优先补强高风险确认、渐进式澄清、真实联网与迁移策略等深化能力。
3. 最后处理 `INFO`，把 UI 表达与文档卫生继续打磨。

## 建议反馈闭环
- 每个 `BLOCKER/WARNING` 生成一条独立缺陷或整改任务，附带复现证据、影响 FR、预期行为、修复证据。
- 修复完成后重新跑与该问题直接对应的 contract / integration / frontend / browser 验证，不接受“只改代码不补证据”。
- 在下一轮总验收前，先同步 `tasks/*.md` 与 `module-state.json`，避免再次出现状态漂移。
