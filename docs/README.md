# 文档目录

## 说明

本目录只保留**当前仍参与研发体系解释或执行**的少量文档。

以下内容**不再保留**：

- 旧流程说明
- 历史审计报告
- 基于已删除项目产物的路径说明
- 作为过去错误案例的长篇复盘文档

这些材料如果继续常驻 `docs/`，会与当前核心规范产生竞争，削弱单一事实源。

## 当前有效文档

### 1. 规范主入口

规范主入口不在 `docs/`，而在以下位置：

- `.cursor/commands/README.md`
- `.cursor/rules/specify-rules.mdc`
- `.specify/templates/**`
- `.specify/scripts/**`
- `.specify/harness/**`

所有研发流程解释、阶段顺序、门禁要求，以以上文件为准。

### 2. 本目录保留文档

- `研发体系问题与治理原则.md`
- `DEFECT_WORKFLOW_DESIGN.md`

## 使用原则

1. 当 `docs/` 与核心命令、规则、脚本冲突时，以核心命令、规则、脚本为准。
2. `docs/` 只负责补充背景、原则和执行说明，不得再形成第二套流程入口。
3. 新增文档前，必须先判断它是否真的会提升当前体系；若只是历史记录或长篇复盘，应避免重新进入活跃文档层。
