---
description: 指挥官模式自动执行 tasks.md 中的任务. 主对话作为轻量指挥官, 派发子代理(工人)执行具体任务, 支持断点续传.
---

## 用户输入

```text
$ARGUMENTS
```

在继续之前, 你**必须**考虑用户输入(如果不为空).

支持的参数:
- 无参数 / `continue` / `继续`: 自动从 tasks.md 中找到下一个未完成批次并执行
- `阶段 N` 或 `phase N`: 指定执行某个阶段
- `T001-T010`: 指定执行某个任务范围

---

## 核心架构: 指挥官 + 子代理工人

```
主对话(指挥官) ─── 轻量级, 只做调度和验证, 不写业务代码
    │
    ├── 读取 tasks.md → 规划批次
    ├── 派发子代理 A (工人) → 执行 T028: 创建 Intent ORM
    ├── 派发子代理 B (工人) → 执行 T029: 创建 Slot ORM
    ├── 派发子代理 C (工人) → 执行 T030: 创建 TrainingData ORM
    ├── (等待所有工人返回)
    ├── 验证产物 → 标记 tasks.md [X]
    ├── 派发下一批...
    └── 输出进度报告
```

**为什么这样设计**:
- 指挥官不读 spec.md/plan.md 全文, 上下文始终保持轻量
- 每个子代理有独立的上下文窗口, 不受主对话累积影响
- 标记为 [P] 的并行任务可同时派发多个子代理, 真正并行执行
- 即使对话很长, 指挥官本身不会溢出(因为重活都在工人那边)

## 执行流程

### 第一步: 环境检查(仅本对话首次运行)

1. 运行 `.specify/scripts/powershell/check-prerequisites.ps1 -Json -RequireTasks -IncludeTasks`, 解析 FEATURE_DIR 和 AVAILABLE_DOCS. 所有路径必须是绝对路径. 对于参数中的单引号如 "I'm Groot", 使用转义语法: 例如 'I'\''m Groot'(或尽可能使用双引号: "I'm Groot").

2. **检查清单状态**(如果 FEATURE_DIR/checklists/ 存在):
   - 扫描并统计已完成/未完成项目
   - 未完成则询问用户是否继续

3. **首次运行验证**(tasks.md 中无 `[X]` 时):
   - 基于 plan.md 技术栈创建/验证忽略文件(.gitignore 等)

### 第二步: 进度扫描与批次规划

4. **读取 tasks.md 并扫描进度**(指挥官只读 tasks.md, 不读其他 spec 文档):
   - 统计: 总数、已完成 `[X]`、未完成 `[ ]`
   - 找到当前阶段(第一个含未完成任务的阶段)
   - **输出进度仪表盘**:
     ```
     ╔══════════════════════════════════════════════════╗
     ║  项目进度: SmartChef 智能对话管理平台              ║
     ╠══════════════════════════════════════════════════╣
     ║  总任务: 145  已完成: 45  待完成: 100              ║
     ║  当前阶段: 阶段 4 - US2 知识库管理                 ║
     ║  本批次: T038~T051 (14 个任务)                    ║
     ║  总进度: ████████░░░░░░░░░░░░ 31.0%               ║
     ╚══════════════════════════════════════════════════╝
     ```

5. **智能批次规划**:
   - **默认**: 以"阶段"为单位
   - **大阶段(>15 任务)自动拆分为子批次**:
     * 子批次 A: 测试任务(TDD 先行)
     * 子批次 B: ORM 模型 + Schema(数据层)
     * 子批次 C: 服务 + API 路由(逻辑层)
     * 子批次 D: 前端组件(展示层)
   - **小阶段(<5 任务)可合并**
   - 直接执行, 不等待用户确认

### 第三步: 派发子代理执行任务

6. **为每个任务/任务组构造子代理指令**:

   指挥官为每个子代理组装一条**自包含的任务指令**, 格式如下:

   ```
   你是 SmartChef 项目的开发工人. 请完成以下任务:

   ## 任务
   T028 [US1] 创建 Intent ORM 模型 `backend/app/models/intent.py`：按 data-model.md Intent 表

   ## 必读文档(只读你需要的)
   - 读取 `specs/master/data-model.md` 中 Intent 表的定义
   - 读取 `specs/master/plan.md` 的"技术背景"部分了解 ORM 框架(SQLAlchemy async)
   - 读取 `backend/app/models/base.py` 了解基类定义

   ## 编码规范
   - Python 3.11+, SQLAlchemy 2.x async 模式
   - ORM 模型继承项目 BaseModel(见 base.py)
   - 中文注释

   ## 交付
   创建文件 `backend/app/models/intent.py`, 确保无 linter 错误.
   完成后回复: 已创建的文件路径和关键设计决策.
   ```

7. **派发策略**:

   **并行任务([P]标记)** → 同时派发多个子代理(最多 4 个并行):
   ```
   同时派发:
     子代理 A → T028 Intent ORM
     子代理 B → T029 Slot ORM
     子代理 C → T030 TrainingData ORM
     子代理 D → T031 Pydantic Schema
   等待全部返回 → 验证 → 标记 [X]
   ```

   **顺序任务(无[P])** → 逐个派发:
   ```
   派发子代理 → T032 意图管理服务(依赖 T028-T031 的 ORM 模型)
   等待返回 → 验证 → 标记 [X]
   派发子代理 → T033 意图 API 路由(依赖 T032 的服务)
   等待返回 → 验证 → 标记 [X]
   ```

   **TDD 顺序**: 测试任务在对应实现任务之前执行.

   **子代理类型选择**:
   - 简单任务(单文件创建, 如 ORM 模型) → `model: fast` 节省成本
   - 复杂任务(多文件联动, 如 NLU Pipeline) → 默认模型
   - Shell 操作(如 Alembic 迁移、npm install) → `subagent_type: shell`

### 第四步: 验证与进度同步

8. **子代理返回后, 指挥官执行验证**:
   - 检查目标文件是否已创建/修改
   - 运行 linter 检查关键文件
   - 如果子代理报告错误 → 记录错误, 该任务保持 `[ ]`
   - 如果验证通过 → **立即**在 tasks.md 中标记 `[X]`

9. **即时进度同步**:
   - 每完成一个任务立即写入 tasks.md, 不等批次结束
   - 防止意外中断导致进度丢失

### 第五步: 循环与交接

10. **批次完成后自动判断**:
    - 当前阶段还有未完成任务 → 继续派发
    - 当前阶段全部完成 → 输出阶段完成报告, 开始下一阶段
    - **主动停止条件**(任意一条触发):
      * 已完成 3 个以上阶段
      * 本对话中派发的子代理总数超过 30 个
      * 遇到子代理连续失败 3 次
    - **停止时输出**:
      ```
      ✅ 本次完成: 阶段 3 (T026~T037), 阶段 4 (T038~T051)
      总进度: 51/145 (35.2%)

      ⏭ 下一步: 请开启新对话, 运行:
         /implement continue
      将自动从 阶段 5 (T052) 继续执行.
      ```

## 子代理指令模板

指挥官在派发子代理时, **必须**在指令中包含以下要素:

1. **任务 ID 和描述**: 精确的任务内容
2. **必读文档路径**: 告诉工人读哪些文件(具体到文件名和章节)
3. **已有代码依赖**: 如果任务依赖已创建的文件, 列出路径
4. **编码规范**: 简要的技术约束(从 plan.md 提取的关键点)
5. **交付物**: 需要创建/修改的文件, 完成标准

**关键: 指挥官不要把文档内容复制到指令里, 只告诉工人文件路径, 让工人自己去读.**

### 按任务类型的文档映射

| 任务类型 | 子代理需读取的文档 |
|---------|-----------------|
| ORM 模型 | data-model.md + models/base.py |
| Pydantic Schema | data-model.md + 对应 ORM 模型文件 |
| API 路由 | contracts/ 中对应 yaml + 对应 service 文件 |
| 业务服务 | spec.md 中对应用户故事 + 对应 ORM 模型 |
| 前端页面 | spec.md 中对应验收场景 + 对应 API 路由文件 |
| 测试 | spec.md 中验收场景 + contracts/ + 被测代码 |
| NLU 模块 | research.md + plan.md NLU 架构部分 |
| 数据库迁移 | 本阶段新增的 ORM 模型文件 |
| 配置/脚本 | plan.md 技术背景部分 |

## 错误处理

- 子代理失败(文件创建失败、linter 错误等): 记录错误, 保持 `[ ]`, 继续其他任务
- 连续失败 3 次: 停止并报告, 建议用户手动排查
- 阻塞型依赖失败(如 T008 失败导致后续无法进行): 立即停止, 报告问题

## 关键原则

- **指挥官零业务代码**: 主对话只做调度, 不亲自写代码, 上下文始终轻量
- **子代理自包含**: 每个工人的指令包含完成任务所需的全部信息(文件路径, 不是文件内容)
- **断点续传**: tasks.md 的 `[X]` 标记 = 持久化进度, 跨对话可靠恢复
- **即时保存**: 每个任务完成立即标记, 不攒批
- **并行最大化**: [P] 标记的任务用多个子代理同时执行
- **按需读取**: 工人只读自己需要的文档, 不加载全部

注意: 此命令假设 tasks.md 中存在完整的任务分解. 如果任务不完整或缺失, 建议首先运行 `/tasks` 重新生成任务列表.
