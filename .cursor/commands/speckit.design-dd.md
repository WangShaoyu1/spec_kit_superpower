# Speckit Design-DD - 详细设计

## 目的
将架构设计转化为**可编码的技术细节**，定义数据模型、状态机、算法逻辑和边界条件。

**核心规范**: `specs/_template/dd-template.md` — 所有 DD 设计 MUST 遵循此模板。

## 输入
- `specs/{branch}/spec.md` - 业务需求 (含模块映射表 + FR 标签)
- `specs/{branch}/pd-all/` - 产品交互设计（交互操作 → API 完整性校验源）
- `specs/{branch}/ad/` - 架构设计（ad-global.md + ad-<module>.md，或单文件 ad.md）
- `specs/_template/dd-template.md` - DD 设计规范 (框架级模板)

## 前置 Gate（MUST）

1. 从仓库根目录运行 `.specify/scripts/powershell/check-prerequisites.ps1 -Json -RequireDesign`，解析 `FEATURE_DIR`
2. 若当前采用模块级 rollout，先运行 `.specify/scripts/powershell/get-module-rollout.ps1 -Json`，确认 `MasterAgent` 选中的目标模块
3. 紧接着运行 `.specify/scripts/powershell/validate-stage-gates.ps1 -Stage dd -Module <target-module> -Json`（非模块模式可省略 `-Module`）
4. 若返回 `status=blocked` 或存在任一 `BLOCKER` 失败码，必须先修上游制品，不得继续生成 DD
5. 若返回 `WARNING`，必须在 DD 文档中显式继承风险，不得把条件准入能力默认视为已设计完成

## 执行流程

### Phase 1: 数据模型设计
为每个关键实体定义字段级规格：

```markdown
## 实体: {实体名称}

| 字段 | 类型 | 约束 | 默认值 | 说明 |
|-----|------|-----|--------|------|
| {字段名} | {数据类型} | {非空/唯一/外键} | {默认值} | {业务含义} |

### 索引
- {索引名称}: {字段列表} - {用途}

### 关系
- 与 {实体B}: {一对一/一对多/多对多}，通过 {字段}
```

### Phase 2: 状态机设计
为有状态实体定义完整状态机：

```markdown
## 状态机: {实体名称}

状态: [状态A, 状态B, 状态C, ...]
初始状态: {状态A}

转移规则:
1. {状态A} → {状态B}: 触发条件 {条件描述}, 操作 {副作用}
2. {状态B} → {状态C}: 触发条件 {条件描述}, 校验 {前置条件}
3. {状态B} → {状态A}: 触发条件 {回滚条件}
```

### Phase 3: 算法与业务逻辑
为核心算法编写伪代码/流程图：

```markdown
## 算法: {算法名称}

输入: {输入参数及类型}
输出: {输出结果及类型}

步骤:
1. {步骤1描述}
2. {步骤2描述}
3. {条件判断}
   - 如果 {条件A}: {处理A}
   - 如果 {条件B}: {处理B}
4. {步骤4描述}

边界条件:
- {边界1}: {处理方式}
- {边界2}: {处理方式}
```

### Phase 4: 错误码与异常定义
定义完整的错误码体系：

```markdown
## 错误码体系

| 错误码 | 含义 | 触发场景 | 用户提示 | 重试策略 |
|--------|------|---------|----------|---------|
| {E001} | {错误描述} | {场景} | {展示文案} | {是否可重试} |
```

### Phase 5: 权限点与角色设计
定义能力模型：

```markdown
## 权限点定义

| 权限点ID | 权限名称 | 操作范围 | 默认角色 |
|---------|---------|---------|---------|
| {perm_xxx} | {名称} | {可执行的操作} | {admin/editor/viewer} |

## 角色与权限映射

| 角色 | 权限点列表 |
|------|-----------|
| {角色A} | {perm_001, perm_002, ...} |
```

### Phase 6: 配置项定义
定义系统级和租户级配置：

```markdown
## 配置项

| 配置项 | 类型 | 默认值 | 范围 | 说明 |
|--------|------|--------|------|------|
| {config_key} | {类型} | {默认值} | {最小-最大} | {业务含义} |
```

## 输出产物

产出物结构取决于模块数量（遵循 `dd-template.md` 规则）：

### 模块数 ≤ 3：单文件

```yaml
# specs/{branch}/dd.md
```

### 模块数 > 3：文件夹

```
specs/{branch}/dd/
├── README.md          # 索引（模块列表、实体数、错误码数、状态）
├── dd-global.md       # 全局详设（共享实体、错误码体系、RBAC 权限、系统配置、种子数据）
└── dd-<module>.md     # 各模块详细设计
```

```yaml
# 每个 dd-<module>.md 包含：
---
version: 1.0
based_on: 
  - spec.md
  - ad/ (ad-global.md + ad-<module>.md)
  - pd-all/pd-<module>/ (交互原型)
---

# 1. 数据模型（字段级、索引、关系、ER 图）
# 2. 状态机（状态/转移/触发条件/副作用）
# 3. 核心算法（伪代码 + 边界条件）
# 4. 错误码（模块前缀 E{xx}xxx）
# 5. 配置项与常量
# 6. API 实现映射（AD 端点 → 实现细节）
```

## DD 完整性检查清单

- [ ] 每个关键实体都有字段级定义
- [ ] 所有状态机转移都有触发条件和校验规则
- [ ] 核心算法有伪代码和边界条件处理
- [ ] 错误码覆盖所有业务异常场景
- [ ] 权限点粒度适合业务需求
- [ ] 配置项有默认值和合法范围
- [ ] 数字/字符串常量有明确的约束（长度、精度、枚举值）
- [ ] AD 中定义的每个 API 端点都有对应的实现映射
