## 用户输入

```text
$ARGUMENTS
```

在继续之前，你**必须**考虑用户输入（如果不为空）。

## 范围控制

根据用户输入确定验证范围：

| 用法 | 范围 |
|------|------|
| `/speckit.smoke` | **全量**：遍历所有页面 |
| `/speckit.smoke [module-name]` | **模块级**：仅验证指定模块的页面（使用 rollout key，如 `pd-monitoring`） |
| `/speckit.smoke [page-path]` | **页面级**：仅验证指定页面（如 `/monitoring/device-logs`） |

## 目标

在真实浏览器中执行探索性冒烟验证，发现**脚本化测试无法覆盖**的问题。

> 本命令补齐测试金字塔中**视觉渲染层**的盲区，与 E2E 脚本化测试互补。

### 覆盖的问题类型（9 项检查，25+ 项）

#### 一、页面可达性 / 路由层面
- 页面白屏：路由已注册但组件渲染为空（如懒加载失败、ErrorBoundary 吞异常）
- 404 / 403 跳转：路由未正确配置、鉴权逻辑错误导致可达页面被拦截
- 永久 Loading：页面挂载后 Spinner 始终不消失（数据请求卡死或 Promise 未 resolve）
- 空数据白屏：列表无数据时未渲染 Empty 占位组件，用户看到空白内容区

#### 二、数据层面（API ↔ 前端衔接）
- API 字段与前端 Table `dataIndex` / 组件字段名不匹配 → 显示 `undefined`
- 数据格式错误：日期显示 ISO 原始格式而非本地化格式、数字显示 `NaN`
- 枚举值未映射：状态列显示英文原文 `active` 而非中文 `启用`
- 空值/null 处理缺失：字段为 null 时显示 `NaN`、`Invalid Date`、或页面崩溃
- 分页元信息不一致：分页器显示"共 100 条"但实际只有 5 条

#### 三、视觉/布局层面
- 容器溢出：Table 横向溢出、内容撑破卡片、出现不期望的滚动条
- 文本截断异常：长文本没有 ellipsis、或截断后无 Tooltip 可查看全文
- 空状态缺失：列表无数据时白屏，而非显示 Empty 占位组件
- Loading 状态缺失或残留：页面加载时无 Spinner；或数据已到但 Spinner 不消失
- 样式/主题不一致：某个页面的卡片圆角、阴影、字体与其他页面不统一

#### 四、交互/行为层面
- 表单提交后列表不刷新：新增成功但列表没有出现新数据
- 弹窗/抽屉残留状态：关闭编辑弹窗后再点新增，表单里还残留上次的数据
- 删除后列表不更新：删除成功提示出现但列表仍显示该条记录
- 搜索/筛选不生效：输入关键词点搜索，列表无变化或结果不正确
- 重复提交：快速双击提交按钮，创建了两条重复记录
- 路由/导航状态错误：侧边栏高亮不正确、浏览器后退行为异常

#### 五、运行时错误层面
- 控制台 JS Error：`TypeError`、`ReferenceError` 等运行时错误
- React 警告：`key` prop 缺失、`useEffect` cleanup 遗漏、废弃 API 警告（如 `bordered` → `variant`）
- 网络请求异常：页面发出意料之外的 4xx/5xx 请求
- 接口调用冗余：页面加载时同一接口被调用 2-3 次

#### 六、权限可见性层面
- 权限按钮未隐藏：无权限的用户能看到"删除"按钮，点击后才报 403
- 页面级权限失效：无权限用户直接输入 URL 仍可访问受限页面

#### 七、运行时性能感知
- 接口调用冗余/瀑布流：页面加载时请求链过长，导致可感知的延迟
- 页面加载体感：首屏内容 > 3 秒仍未渲染，用户体验不佳

#### 八、PD 功能符合性
- 对照 PD 交互稿中对应模块的页面，核查功能覆盖度（不要求排版一致，只核对功能）：
  - PD 中定义的按钮/操作入口，页面上是否存在
  - PD 中定义的状态流转（如 草稿→发布→归档），页面上是否可触达
  - PD 中定义的表单字段，新增/编辑弹窗中是否齐全
  - PD 中定义的筛选/搜索条件，页面上是否实现
  - 功能差距过大时，标记为**严重**问题

## 前置条件

执行前 MUST 确认：
1. 后端服务已启动（`uvicorn app.main:app` 或 `python -m uvicorn app.main:create_app --factory`）
2. 前端开发服务器已启动（`npm run dev`）
3. 数据库已初始化（种子数据已导入）
4. 至少有一个可登录的用户账号
5. 若是模块级验证，先运行 `.specify/scripts/powershell/validate-stage-gates.ps1 -Stage browser -Module <target-module> -Json`
6. 目标模块存在 `ai-pd/ai-<module>.md`，并作为 smoke 的能力核对主输入

## 执行流程

### Phase 1: 准备

1. 使用 browser 工具打开前端页面（默认 `http://localhost:5173`）
2. 执行登录操作（使用默认 admin 账号或用户指定的账号）
3. 确认登录成功，进入主界面
4. 若是模块级验证，读取 `module-rollout.json` 中该模块的 `browser_stage` 配置，确认 `ui_smoke / business_e2e / quality_probes`
   - 若模块为 `critical`，必须显式看到 `page_boundary_parity` 与 `route_navigation_chain`
   - 若缺少上述探针，直接按 `BLOCKER` 结束，不得进入“手工补脑”式 smoke
5. 优先读取当前模块 `ai-pd/ai-<module>.md`，再读取当前模块 plan / `tasks/` 中该范围对应模块的核心业务链路与显式未完成声明
6. 若目标模块仍存在 `Stub / Blocked By` 且影响核心链路，必须在报告中明确标记为未通过，禁止用"页面可访问"替代结论

### Phase 2: 逐页验证

根据范围控制，对每个目标页面执行以下 **9 项检查**：

#### 检查 1: 页面可达性
- 导航到页面 URL
- 确认页面不白屏、不显示 404/403
- 确认页面主要内容区域已渲染（非空白或永久 loading）
- 空数据时确认有 Empty 占位组件（非白屏）
- 对 critical 模块，必须核对 PD 定义的页面边界是否都存在正式路由入口，不允许用单页聚合替代多页主流程

#### 检查 2: 控制台健康
- 检查浏览器 console 输出：
  - **JS Error** → MUST 记录，标记为严重
  - **React 警告**（key 缺失、废弃 API、useEffect 清理）→ 记录为一般
  - **网络请求 4xx/5xx** → 记录为严重
  - **同一接口重复调用**（≥2 次）→ 记录为一般

#### 检查 3: 数据渲染校验
如果页面包含列表/表格：
- 确认 Table 列头与实际数据列对应（无 `undefined`、无全空列）
- 确认数据类型正确（日期显示为本地化格式、数字非 NaN、百分比有 `%`）
- 确认枚举值已映射为中文（如 `active` → `启用`、`command` → `指令`）
- 确认 null/空值有合理占位（如 `-` 或 `暂无`，而非空白或 `null`）
- 确认分页器存在且总数与实际数据一致

#### 检查 4: 布局完整性
- 截图检查，确认：
  - 无水平溢出（页面不出现横向滚动条，除非是 Table 设计如此）
  - 侧边栏/头部/内容区域不重叠
  - 文本不被截断到不可读（ellipsis 正常，长文本有 Tooltip）
  - Loading 状态正常（加载时有 Spinner，数据到达后消失）
  - 样式/主题一致（卡片圆角、阴影、字体与其他页面统一）

#### 检查 5: 关键交互
在页面上执行**主要操作**（不需要穷举，覆盖核心路径即可）：
- 点击「新增/创建」按钮 → 弹窗/抽屉正常弹出，表单可填写
- 点击「编辑」 → 弹窗/抽屉弹出，数据正确回填
- 关闭弹窗后重新打开 → 表单无残留数据
- 点击「删除」 → 确认弹窗正常，删除后列表立即更新
- 表单提交后 → 列表自动刷新，新数据可见
- 使用搜索/筛选 → 列表正确刷新
- 翻页 → 数据正确切换

#### 检查 6: 运行时性能感知
- 页面首屏渲染 > 3 秒 → 记录为一般
- Network 面板观察同一接口是否被重复调用 → 记录为一般
- 操作后（如提交表单）响应 > 2 秒无反馈 → 记录为一般

#### 检查 7: 权限可见性（如有多角色）
- 切换到非管理员角色登录
- 检查受限功能的按钮是否隐藏（而非点击后才报 403）
- 直接输入受限页面 URL → 应跳转 403 页面而非白屏

#### 检查 8: PD 功能符合性
- 读取当前页面对应的 AI-PD 与 PD 交互稿（`specs/{branch}/ai-pd/ai-<module>.md` + `specs/{branch}/pd-all/pd-<module>/`）
- 对照核查（不要求排版一致，只核对功能覆盖度）：
  - AI-PD 中定义的 capability / action / data / exception，页面上是否可验证
  - PD 中定义的页面数、详情页/子页和主导航链路，页面上是否存在
  - PD 中定义的按钮/操作入口，页面上是否存在
  - PD 中定义的状态流转（如 草稿→发布→归档），页面上是否可触达
  - PD 中定义的表单字段，新增/编辑弹窗中是否齐全
  - PD 中定义的筛选/搜索条件，页面上是否实现
  - **排除项**：仅允许排除 AI-PD 中标记为 `instructional / non-actionable-note` 的内容；不能仅因其位于 Drawer/Modal 就自动排除
  - **功能差距过大时标记为严重**，缺少个别字段标记为一般
  - **PD 符合性为必检维度**：即使其他 8 项检查全部通过，PD 功能覆盖率不足仍应标记页面为「未通过」
  - 发现 PD 差距时 MUST 自动生成缺陷文件（category: "PD 功能缺失"），无需人工触发

#### 检查 9: 业务链路冒烟 [MUST]

每个模块至少走通一条"创建 → 使用 → 验证"的完整业务链路。

**检查方法**: 通过浏览器或 API 调用，验证核心流程端到端可用（非仅 UI 渲染）。

**各模块核心链路**:
- **用户管理**: 创建账号 → 调整角色/权限 → 列表与权限矩阵回读一致
- **指令库**: 新建库 → 新建数据集 → 添加意图 → 创建模型 → 训练 → 状态变为 trained → 评估 → testable → 发布
- **对话方案**: 创建方案 → 绑定指令库 → 发布 → 测试对话返回有意义结果（非占位符）
- **批量测试**: 创建批次 → 添加用例 → 执行 → 结果包含真实准确率/延迟
- **知识库**: 上传文档 → 索引完成 → 检索返回相关结果
- **监控**: 产生请求日志 → 仪表盘指标非全零

**判定标准**:
- 链路中任何步骤返回占位符/假数据/状态卡死 → **FAIL**
- 推理/分析结果为硬编码 mock 值 → **FAIL**
- API 返回 501 (Not Implemented) → **FAIL**（桩代码未清除）
- 前端在未获得真实结果前显示"成功/已完成/已生成" → **FAIL**
- 进度条、统计卡、结果摘要使用硬编码值 → **FAIL**

| # | 页面 | 检查维度 | 描述 | 严重程度 |
|---|------|---------|------|----------|

| S3 | /page-c | 布局完整性 | 横向溢出 | 一般 |

## 页面清单获取方式（全量模式）

全量冒烟时，页面清单**不在本规范中硬编码**，而是从项目中动态获取：

1. **首选**：读取前端路由配置文件（如 `App.jsx` / `router.js`），提取所有注册的页面路径
2. **备选**：读取 PD 交互稿索引（`specs/{branch}/pd-all/pd-index.md` 或 `pd-hub.html`），获取模块与页面的映射
3. **兜底**：读取侧边栏导航配置（如 `MainLayout.jsx` 中的 `MENU_ITEMS`），提取所有可导航路径

按以下顺序遍历：
- 先遍历所有列表页
- 再从列表页中获取有效 ID，导航到详情页（列表为空则跳过）
- 含子页面的模块（如有子菜单），逐一遍历子页面
